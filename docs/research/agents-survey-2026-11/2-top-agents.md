# How leading AI agents work inside

Desk research, 27 November 2026. For DESMAN(P), the central question is how much verified work an agent can finish before it runs out of requests, context, or time. The systems below expose different parts of that problem. The open repositories show actual control flow, vendor engineering posts document selected design choices, and benchmark boards measure specific model–harness combinations. For closed products, the account below stops at mechanisms the vendor has disclosed. The **For DESMAN:** lines and the final ranking are design proposals for the existing Python and SQLite prototype.

## Interactive and background coding agents

### Claude Code

Anthropic made Claude Code generally available on 22 May 2025. It runs an iterative gather-context, act, and verify loop with file, search, edit, and terminal tools. Project `CLAUDE.md` instructions and auto memory can supply persistent context. Skills supply procedures on demand, while subagents get their own context window, prompt, tools and permissions and report back to the parent. The built-in Explore subagent is a concrete example of delegating a repository scan without pulling every file into the main session. Hooks run at lifecycle events, so a pre-tool hook can enforce a rule even when the model forgets it. [GA announcement](https://www.anthropic.com/news/claude-4), [agent loop](https://code.claude.com/docs/en/how-claude-code-works), [skills](https://code.claude.com/docs/en/skills), [subagents](https://code.claude.com/docs/en/sub-agents), [hooks](https://code.claude.com/docs/en/hooks-guide).

Plan mode lets the model inspect and propose changes before it gets general editing authority. Permission rules and the selected interaction mode govern the tool call. Shell sandboxing can enforce filesystem and network limits, using bubblewrap on Linux and Seatbelt on macOS. Claude Code automatically compacts growing context and supports manual `/compact`. Rewind can restore conversation or tracked file edits, but external effects and changes made by shell commands can fall outside the file checkpoint. Anthropic's November 2025 long-running harness write-up uses a durable feature list, progress file and Git commits so a fresh session can pick up incremental work and rerun a basic end-to-end check. That is a separate experimental harness pattern from Claude Code's built-in rewind. [Permissions](https://code.claude.com/docs/en/permissions), [shell sandbox](https://code.claude.com/docs/en/sandboxing), [checkpoint scope](https://code.claude.com/docs/en/checkpointing), [long-running harness](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents).

**For DESMAN:** Give each DAG step a small, persisted handoff with its objective, remaining checks, artifact IDs and the last verified revision. Reload approved instructions and actual permissions when a new worker takes over.

### OpenAI Codex CLI and cloud

OpenAI released the local Codex CLI on 16 April 2025. Codex cloud entered research preview on 16 May 2025 and reached general availability on 6 October 2025. The open-source local CLI drives a Responses API loop: send context and tools, execute returned calls under policy, append results, and repeat until the model answers or the turn ends. OpenAI's January 2026 engineering account describes stable prompt prefixes for caching and automatic compaction above a token threshold. Its compaction endpoint returns a smaller state with an opaque component, which is useful within that API but would be a poor interchange format across DESMAN providers. The CLI discovers `AGENTS.md` instructions from global and repository scopes, with nearer instructions taking precedence. [CLI launch](https://openai.com/index/introducing-o3-and-o4-mini/), [cloud launch](https://openai.com/index/introducing-codex/), [GA](https://openai.com/index/codex-now-generally-available/), [agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/), [instruction discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Codex treats permitted filesystem and network access separately from whether the user is asked to escalate. OpenAI's 18 November 2026 write-up documents Linux bubblewrap plus seccomp-BPF and macOS Seatbelt. The cloud service runs on OpenAI-managed computers and continues independently of the user's device. The documented legacy cloud lifecycle checks out a selected revision, runs setup in a container, applies agent network settings, loops through commands and checks, and supplies a diff. Current cloud documentation distinguishes the newer environment experience from legacy environments still used for some integrations. [Sandbox internals](https://openai.com/index/inside-the-codex-sandbox/), [cloud service](https://help.openai.com/en/articles/20001545-using-codex-cloud), [legacy lifecycle](https://learn.chatgpt.com/docs/environments/cloud-environment).

**For DESMAN:** Use a scoped instruction file for test commands and conventions, and enforce capabilities in the executor. Persist any approved expansion as a scoped decision tied to the actual action. Keep cross-provider resume data readable and reconstructible from SQLite.

### Cognition Devin

Devin is a hosted software-engineering agent with its own working machine. Devin 2.0, released 3 April 2025, added interactive planning and a repository wiki built from indexing. Devin 2.2, released 24 February 2026, added desktop computer use for testing changes and attempting fixes. Cognition's September 2024 update describes reusable machine snapshots, procedural playbooks, and Knowledge suggestions prompted by feedback. Its 2026 verification write-up describes turning environment setup into a YAML blueprint that produces snapshots for future sessions and collecting evidence from testing an application. A reviewer can assess a changed UI from a recording of the run alongside the patch. Cognition discloses these session mechanics, while its full runtime policy and model-routing details remain opaque. [Devin 2.0](https://cognition.com/blog/devin-2), [Devin 2.2](https://cognition.com/blog/introducing-devin-2-2), [snapshots and Knowledge](https://cognition.com/blog/sept-24-product-update), [verification write-up](https://cognition.com/blog/testing-development).

**For DESMAN:** Turn repeatable jobs into human-reviewed playbook nodes, each with known inputs, setup requirements and required proof. Treat an agent's learned lesson as a candidate node requiring approval before it becomes an instruction for other workers.

### Cursor Agent and Background Agents

Cursor's interactive editor agent searches a codebase, edits it and runs commands. Cursor 0.50 introduced Background Agents on 15 May 2025. Version 1.7 on 29 September 2025 added Plan Mode and hooks and documented sandboxed terminals. Hosted Cloud Agents use isolated AWS VMs with internet access by default and repository credentials scoped through the GitHub integration. The dedicated environment lets an agent build and test independently of a developer's editor session. Cursor exposes local checkpoints and publishes release notes for their persistence, but its complete context packing and scheduling logic is proprietary. [Agent mode](https://cursor.com/help/ai-features/agent), [0.50](https://cursor.com/changelog/0-50), [1.7](https://cursor.com/changelog/1-7), [cloud network and secrets](https://prod.cursor.com/docs/cloud-agent/security-network), [release notes](https://prod.cursor.com/docs/release-notes).

Cursor's semantic-search study is an unusually direct comparison of a retrieval tool. On its internal repository question-answering evaluation, Cursor reports 12.5% higher accuracy on average with semantic search available. Its search stack also uses grep, and its embedding model learns from files agents eventually opened in past sessions. The 12.5% applies to repository question answering. Cursor's separate online experiments use proxies such as code retention. [Retrieval study](https://cursor.com/blog/semsearch).

**For DESMAN:** Start with SQLite full-text search and a bounded symbol index over approved documents and worktrees. Measure whether better initial localization reduces model turns before committing to an embedding service.

### Gemini CLI

Google released Gemini CLI as an open-source terminal agent on 25 June 2025. Its core orchestrates model turns and tool execution, with `GEMINI.md` context, a compression command, a todo tool, a policy engine for tool decisions, and configurable sandboxing. Its checkpointing facility captures workspace and conversation state around file modifications. Plan mode provides read-only exploration and a plan approval transition, although the v0.64.0 release on 13 October 2026 added unattended plan execution for non-interactive workflows. On 18 June 2026 the individual Code Assist access path, including Google AI Pro and Ultra, stopped serving Gemini CLI requests. Google directed affected users toward Antigravity CLI. Google Cloud Code Assist Standard and Enterprise were outside that consumer cutoff, and the open repository continued publishing releases. [Launch](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemini-cli-open-source-ai-agent/), [core](https://geminicli.com/docs/core/), [commands](https://geminicli.com/docs/reference/commands/), [todo tool](https://geminicli.com/docs/cli/tutorials/task-planning/), [policy engine](https://geminicli.com/docs/reference/policy-engine/), [checkpoints](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/checkpointing.md), [plan mode](https://geminicli.com/docs/cli/plan-mode/), [release notes](https://geminicli.com/docs/changelogs/), [transition](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/).

**For DESMAN:** Give the interlocutor a read-only plan preview for consequential requests. Store provider access and health separately from worker identity so a disappearing free endpoint triggers a reschedule with the same policy and checkpoint.

### OpenHands

OpenHands is an open coding-agent platform with an inspectable V1 SDK. The SDK paper first appeared on 5 November 2025 and was revised on 22 April 2026 for MLSys. The agent operates over a conversation event stream and pluggable tools and can use a local workspace or a remote Agent Server in an ephemeral Docker or Kubernetes workspace. This gives the client a way to observe the agent and control its lifecycle. The SDK condenser replaces older events with a summary while retaining the recent tail. The implementation explicitly trades smaller requests against the cache invalidation caused by rewriting the prefix. The paper reports fewer system-attributable failures for V1 in its production comparison. That result measures runtime reliability. OpenHands also published a smaller-model example on 31 March 2025. Its Qwen-based OpenHands LM 32B was fine-tuned on task trajectories and reached 37.2% on SWE-bench Verified in the team's evaluation. The score is a historical example of tool-use specialization. [SDK repo](https://github.com/OpenHands/software-agent-sdk), [SDK paper](https://arxiv.org/abs/2511.03690), [condenser](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/context/condenser/README.md), [OpenHands LM 32B release](https://www.openhands.dev/blog/introducing-openhands-lm-32b----a-strong-open-coding-agent-model).

**For DESMAN:** Keep durable tool events and the prompt drawn from those events as two representations. Build a bounded prompt from authoritative state, a compact summary and recent events. Let the coordinator inspect the ledger if the summary omits a failure or a confirmation.

### SWE-agent

SWE-agent's 2024 paper introduces an agent-computer interface with bounded search results, a file viewer and an editor that feeds back lint errors. On SWE-bench Lite, GPT-4 Turbo with this interface resolved 18.0%, a 64% relative increase over its shell-only baseline. The ablations also show that an iterative search interface can induce exhaustive browsing and perform worse than omitting specialized search. This is direct evidence that the result a tool returns can matter as much as the action the tool exposes. [SWE-agent paper](https://arxiv.org/html/2405.15793).

**For DESMAN:** Give smaller models compact search results and structured error feedback. Benchmark those interfaces against the current tools on the same budget.

### mini-SWE-agent

The same team launched mini-SWE-agent in July 2025 as a small model–shell loop with an append-only trajectory. Version 2.0.0, released 11 February 2026, switched from parsing model text for commands to structured tool calls. The shell action is intentionally general, with independent invocations rather than a required persistent interactive shell. The project exposes the runtime and configuration so another evaluator can pin a model, environment and harness version. The benefit of a general shell action versus a narrow tool interface remains model-dependent. [mini-SWE-agent repo](https://github.com/SWE-agent/mini-swe-agent), [v2.0.0](https://github.com/SWE-agent/mini-swe-agent/releases/tag/v2.0.0), [migration details](https://github.com/SWE-agent/mini-swe-agent/blob/main/docs/advanced/v2_migration.md).

**For DESMAN:** Benchmark a thin, budgeted baseline using the existing sandbox and keep tool observation limits fixed. Compare it with targeted search and compact test failure output on the same tasks and cheap models.

### Aider

Aider is a Git-aware terminal pair programmer. Version 0.86.2 was published on 12 February 2026. The October 2023 repository-map design parses definitions and references with Tree-sitter, ranks relationships with a graph algorithm and fits useful signatures into a token budget. This gives the model hints about where to look before it receives full files. Git integration supports automatic commits and undo, and lint or test failures can go back into the editing loop. In September 2024, Aider published its architect/editor mode: one model proposes changes in natural language and a second emits edits in the required format. On Aider's own editing benchmark, o1-preview with a DeepSeek or o1-mini editor scored 85.0%, compared with 79.7% for solo o1-preview. Some pairings scored lower, and the edit format varied across configurations. [Repo-map design](https://aider.chat/2023/10/22/repomap.html), [Git integration](https://aider.chat/docs/git.html), [architect/editor comparison](https://aider.chat/2024/09/26/architect.html), [v0.86.2 package release](https://pypi.org/project/aider-chat/0.86.2/).

**For DESMAN:** Trial a cheap patch writer with named symbols, bounded file slices and an explicit requested behavior. Reserve scarce reasoning quota for localization and ambiguity, and use the existing reviewer to inspect the applied diff and checks.

### Cline

Cline's IDE agent exposes a Plan/Act split and user-configurable approval rules. In the documented Auto Approve workflow the model can classify a terminal command as requiring approval, so that classification has different guarantees from an operating-system sandbox. Cline checkpoints use shadow Git to snapshot workspace changes independently of the user's commit history, and support comparison and restoration. Cline v3.14, released 3 May 2025, expanded checkpoint controls and Gemini cache visibility. [Plan and Act](https://docs.cline.bot/core-workflows/plan-and-act), [auto approve](https://docs.cline.bot/features/auto-approve), [checkpoints](https://docs.cline.bot/core-workflows/checkpoints), [v3.14](https://cline.bot/blog/cline-v3-14-improved-gemini-caching-newrule-command-enhanced-checkpoints-key-updates).

**For DESMAN:** Tie worktree restore points to coordinator checkpoints and keep approval history available after a transcript or file restore.

### Roo Code

Roo Code was a separate fork and product. Its Orchestrator used Boomerang Tasks to hand scoped work and relevant context to a specialized child mode and regain control when the child returned a completion summary. This made the parent responsible for task coordination while the child held the detailed context. The Roo team sunset its extension, Cloud and Router on 15 May 2026 and archived the source as a reference. [Boomerang Tasks](https://roocodeinc.github.io/Roo-Code/features/boomerang-tasks/), [sunset notice](https://github.com/RooCodeInc/Roo-Code-Docs/blob/main/docs/sunset.md).

**For DESMAN:** Require child tasks to return a result, supporting artifact IDs and unresolved items, so the coordinator can resume scheduling after a child completes.

### Goose

Goose is an open CLI and desktop agent originally developed by Block. Its Rust agent connects model providers to extensions, including MCP servers. Recipes package repeatable instructions and extension configuration. Its June 2025 multi-model write-up describes a lead/worker provider that starts with the lead and switches to a cheaper worker after a configured number of turns, with fallback behavior on failure. Goose v1.25.0, released 18 February 2026, consolidated delegation and skill invocation under Summon. Its documentation also describes context compaction as a session concern. The lead/worker mechanism is a concrete routing strategy, although turn count is at best a proxy for task difficulty. [Architecture](https://github.com/aaif-goose/goose/blob/main/documentation/docs/goose-architecture/goose-architecture.md), [lead/worker](https://github.com/aaif-goose/goose/blob/main/documentation/blog/2025-06-16-multi-model-in-goose/index.md), [recipes](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/recipes/recipe-reference.md), [v1.25.0](https://github.com/aaif-goose/goose/releases/tag/v1.25.0), [context management](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/sessions/smart-context-management.md).

**For DESMAN:** Route by role and observed progress. Give narrow extraction and mechanical edits to cheap workers, and escalate repeated invalid outputs, conflicting evidence or stalled verification to a more capable model if quota permits.

### Google Jules

Jules is Google's asynchronous coding agent, launched in public beta on 19 May 2025 and out of beta on 6 August 2025. It clones the repository into a cloud VM, prepares the environment, presents a plan and works toward a diff or pull request. Google added environment snapshots, interactive plan editing and a critic agent in August 2025. Its January 2026 planning critic reviews auto-approved plans before execution. This illustrates the difference between checking a plan for plausibility and having a human authorize the action. The changelog describes product behavior, with limited evidence on how much the critics improve real task outcomes. [Beta](https://jules.google/docs/changelog/2025-05-19), [GA](https://blog.google/innovation-and-ai/models-and-research/google-labs/jules-now-available/), [release history](https://jules.google/docs/changelog), [planning critic](https://jules.google/docs/changelog/2026-01-26-1).

**For DESMAN:** Use the reviewer to flag plan steps with missing dependencies, unspecified verification or ambiguous scope before scheduling them. Persist the proposed plan and critique so the human can inspect the basis for approval.

## General-purpose and research agents

### Manus

Manus is a hosted general-purpose agent. Its 18 July 2025 engineering write-up describes a model repeatedly selecting an action in a VM and receiving observations. The team keeps prefixes stable and serialization deterministic for prefix caching, constrains action selection without constantly rewriting tool definitions, keeps substantial results in the filesystem, and uses a `todo.md` to bring objectives near the end of the prompt. It keeps failed actions visible so the agent has evidence to change course. The write-up is a retrospective on an implementation, with limited public controlled evidence about the size of each effect. Manus announced it was joining Meta in December 2025 and described a return to independent operations in its August 2026 user notice. The notice also describes a data backup and restoration process for affected users. [Engineering write-up](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), [Meta announcement](https://manus.im/en/blog/manus-joins-meta-for-next-era-of-innovation), [2026 user notice](https://manus.im/blog/a-note-to-our-users).

**For DESMAN:** Render a compact checklist from the SQLite DAG, and keep long tool outputs in artifacts addressed by ID. Track cache hits only where providers expose them, and prioritize request count and successful completions where caching offers no quota benefit.

### OpenAI ChatGPT agent and Operator

Operator launched on 23 January 2025 as a browser research preview: a computer-use model interpreted screenshots and issued mouse and keyboard actions in a hosted browser. On 17 July 2025, ChatGPT agent combined graphical and text browsers, a terminal and app access in a virtual computer. The announcement said the standalone Operator site would sunset after a transition. The agent can request human takeover for sensitive input and confirmation before consequential actions. Its system card discusses prompt injection and mistaken actions because the agent reads untrusted material and can act on behalf of an authenticated user. OpenAI documents controls and evaluations, while internal routing and memory policies remain largely undisclosed. [Operator launch](https://openai.com/index/introducing-operator/), [ChatGPT agent launch](https://openai.com/index/introducing-chatgpt-agent/), [system card](https://openai.com/index/chatgpt-agent-system-card/).

**For DESMAN:** Stay with structured web fetch for research. Where an authorized workflow needs an external write, show the exact destination and payload summary through the existing human inbox before executing the confirmed action.

### OpenAI deep research

ChatGPT deep research launched on 2 February 2025 with an o3-derived model optimized for web browsing and analysis. It iteratively searches, inspects sources and synthesizes cited findings. On 24 April 2025 an o4-mini-based lightweight version introduced a cheaper path, including fallback when the full version's limit was reached. The 10 February 2026 update added site restrictions, connected sources and interruption to refine an active run. OpenAI's product descriptions establish these controls and the tool loop. They leave details such as whether the current service delegates specific searches undisclosed. [Launch and dated updates](https://openai.com/index/introducing-deep-research/), [current workflow](https://help.openai.com/en/articles/10500283-deep-research-in-chatgpt), [lightweight API model](https://developers.openai.com/api/docs/models/o4-mini-deep-research).

**For DESMAN:** Begin with a low-quota pass that gathers primary evidence for the most important questions. Escalate unresolved claims individually and allow the human to add domains or steer the investigation through chat.

### Gemini Deep Research

Google launched Gemini Deep Research in the app on 11 December 2024, opened a developer preview via the Interactions API in December 2025, then introduced updated Deep Research and Deep Research Max agents on 21 April 2026. The public API is a job interface with asynchronous execution and polling or streaming. It supports plan review and grounding over web, files and configured MCP tools. Google describes the Max variant as spending more test-time compute on iterative reasoning, search and refinement. It exposes the job lifecycle and source configuration, with limited visibility into how individual searches are scheduled or how the model's context is compacted. [App launch](https://blog.google/products-and-platforms/products/gemini/google-gemini-deep-research/), [API preview](https://blog.google/innovation-and-ai/technology/developers-tools/deep-research-agent-gemini-api/), [April 2026 launch](https://blog.google/innovation-and-ai/models-and-research/gemini-models/next-Generation-gemini-deep-research/), [API documentation](https://ai.google.dev/gemini-api/docs/deep-research).

**For DESMAN:** Make long research runs resumable at the evidence-gathering boundary. If a node loses quota, let another worker pick up the open question and recorded source trail before synthesis.

### Open Deep Research implementations

Hugging Face's February 2025 Open Deep Research uses `smolagents` to write Python actions combining browser and other tools. The authors reported 55.15% on GAIA validation versus 33% when switching the same setup to JSON actions. This is an interface result on one test configuration. For DESMAN the result argues for composing structured tools or using the existing sandbox when a computation warrants it. LangChain's 16 July 2025 Open Deep Research exposes a more structured example: a brief feeds a supervisor, parallel research workers operate on scoped topics, findings are compressed and a final writer synthesizes them. The public implementations show how to reproduce the orchestration while model and search costs depend on the chosen configuration. [Hugging Face implementation and comparison](https://huggingface.co/blog/open-deep-research), [LangChain implementation](https://www.langchain.com/blog/open-deep-research).

**For DESMAN:** Use the existing sandbox for bounded computation and compose ordinary search with structured evidence records. Give the writer the source trail for every compressed worker report.

### Anthropic Research

Anthropic's 13 June 2025 research write-up documents a lead that plans and delegates to independent researchers and a separate citation agent. An Opus 4 lead with Sonnet 4 subagents scored 90.2% higher than single-agent Opus 4 on Anthropic's internal research evaluation. Anthropic also reported that its multi-agent systems used about 15 times the tokens of ordinary chats and that token usage explained 80% of BrowseComp performance variance in its analysis. The comparison changes both orchestration and compute. It favors delegation for questions with genuinely independent branches and gives little reason to convene a cluster for every task. [Anthropic engineering comparison](https://www.anthropic.com/research/multi-agent-research-system).

**For DESMAN:** Fan out only independent, high-value questions. Ask workers for short evidence records with source URLs and passages, cache shared fetches where policy permits, and give the reviewer the original sources when checking synthesis.

## What appears to change outcomes

A September 2026 preprint tested 176 matched settings across four models on SWE-bench Verified and Terminal-Bench 2.1. Context management mattered more at tight window budgets, chiefly by preventing overflow. Rule-based elision before model summarization gave the strongest overall efficiency in the tested configurations. Planning improved weaker-model accuracy and mainly saved cost on stronger models. Another September preprint finds harness effects that vary with model, task and component. Taken with SWE-agent's interface ablations, these results justify testing each additional mechanism against the existing DESMAN loop at the same budget. [Matched harness study](https://arxiv.org/abs/2609.20804), [cross-harness study](https://arxiv.org/abs/2609.32459), [SWE-agent ablations](https://arxiv.org/html/2405.15793).

Verification should use the strongest evidence each task can produce. A patch can be checked against a pinned test suite and inspected as a diff, while a research claim can be checked against the cited passage. A model critic can judge gaps in a plan or relevance of evidence, and an LLM judge can help score unstructured output with a fixed rubric. Treat judge calls and repeated attempts as budgeted actions and check a sample against human decisions. This follows the observable checks in Devin and Jules and the grading failures reported by the benchmark maintainers. Independent rechecking should be selective in desman-global, especially when nodes would all consult the same model or evidence. [Devin verification](https://cognition.com/blog/testing-development), [Jules critic](https://jules.google/docs/changelog/2025-08-083/), [Terminal-Bench verifier revisions](https://www.tbench.ai/news/terminal-bench-4-1).

## Top ideas for DESMAN

Effort estimates are relative to the current prototype. **S** is a localized change, **M** spans existing components, and **L** involves a new protocol or substantial coordination work.

1. **Persist a resume record for every leased step (M)** — Coordinator, executor and SQLite. Record artifact references, remaining checks, the verified revision and the last completed action. Couple writes to the lease generation so a stale worker cannot publish over its replacement. [OpenHands event sourcing](https://arxiv.org/abs/2511.03690), [Anthropic session handoffs](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents).
2. **Run explicit acceptance checks before closing a step (M)** — Reviewer, executor and Improvement Analyst. Have the planner specify expected evidence, retain test and source artifacts, and call a model critic for judgment that the check cannot automate. Benchmark the verifier on both valid variants and intentionally incomplete outputs. [Cognition verification](https://cognition.com/blog/testing-development), [Verified grading audit](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/).
3. **Bound the executor's context cheaply (M)** — Executor and knowledge tree. Limit repetitive outputs first. Keep artifact IDs, failures and the recent tail, then summarize only when needed. Reload human-approved policy and task state from durable storage. Measure model turns, token consumption and completed tasks at each budget. [Condenser implementation](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/context/condenser/README.md), [matched harness study](https://arxiv.org/abs/2609.20804).
4. **Define cheap-first routing with a reserved escalation budget (M)** — Planner, executor and provider scheduler. Assign constrained tasks to cheap models or Ollama when available. Budget per task and provider, respect cooldowns, and escalate on failed checks or stalled progress. Log the actual model and reason for a switch. [Aider model pairing](https://aider.chat/2024/09/26/architect.html), [Goose lead/worker](https://github.com/aaif-goose/goose/blob/main/documentation/blog/2025-06-16-multi-model-in-goose/index.md).
5. **Add bounded repository and document retrieval (S)** — Executor and knowledge tree. Expose file paths, headings and symbol signatures with a small token budget. Check whether search answers arrive in fewer calls before expanding the index. [Aider repo map](https://aider.chat/2023/10/22/repomap.html), [Cursor retrieval study](https://cursor.com/blog/semsearch).
6. **Bind approval to the action and pin the artifact (M)** — Interlocutor, human inbox and Improvement Analyst. Show the actual plan or diff, target, checks and requested scope. Persist the decision against the approved artifact version. Apply prompt and setting changes through the existing human Git commit and revert workflow. [Claude Code permissions](https://code.claude.com/docs/en/permissions), [Codex sandbox](https://openai.com/index/inside-the-codex-sandbox/).
7. **Delegate evidence work within a fixed cluster budget (L)** — desman-global, coordinator and reviewer. Use scoped child assignments that preserve node and source provenance. Reserve independent rechecks for disagreements or consequential conclusions, and run deterministic artifact checks locally where possible. Measure verified work per borrowed request. [Roo handoffs](https://roocodeinc.github.io/Roo-Code/features/boomerang-tasks/), [Anthropic delegation costs](https://www.anthropic.com/research/multi-agent-research-system).
